Perguntas e Respostas

  1. O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?

    Resposta:

    • Commit: grava no repositório local um registo das alterações que estão em staging, acompanhado de uma mensagem descritiva. Fica no histórico local e ainda não chega ao servidor.
    • Push: envia os commits locais para o repositório remoto, atualizando-o.
    • Pop: o comando existente é o git stash pop, que volta a aplicar no diretório de trabalho as alterações guardadas temporariamente com git stash e remove-as do stash.

  2. Quais são as vantagens de usar Branchs num repositório git?

    Resposta:

    Os branches permitem trabalhar em funcionalidades ou correções em paralelo, isoladas do ramo principal (main), que se mantém estável. Facilitam a experimentação (um ramo falhado descarta-se sem consequências) e o trabalho em equipa, pois cada pessoa trabalha no seu ramo e depois integra as alterações com merge ou pull request.

  3. Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em que consistem e como podem ser resolvidos esses conflitos?

    Resposta:

    Um conflito acontece quando o Git não consegue juntar automaticamente duas versões do mesmo ficheiro, normalmente porque as mesmas linhas foram alteradas de forma diferente em cada uma. Nesse caso, o Git para e marca no ficheiro as duas versões.

    Para resolver o conflito, abre-se o ficheiro onde o Git marcou as duas versões, escolhe-se qual delas fica (ou juntam-se as duas) e apagam-se os símbolos que o Git colocou. Por fim, guarda-se o ficheiro e executa-se git add seguido de git commit para concluir.

  4. “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

    Resposta:

    • Clone: cria uma cópia de um repositório remoto no nosso PC, com todo o histórico, e mantém a ligação ao repositório original.
    • Fork: cria uma cópia do repositório na nossa conta do GitHub, independente do original, onde podemos fazer alterações sem ter permissões nele. Essas alterações podem ser propostas ao projeto original através de um Pull Request.
    • Diferença principal: o Clone é uma cópia local (no PC) e o Fork é uma cópia remota (na nossa conta).
